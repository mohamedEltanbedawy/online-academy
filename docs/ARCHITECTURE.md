# Family OS — البنية المعمارية
### Architecture — منصة القرية الرقمية للعائلة

> **الرؤية:** المنصة تتحول من "نظام تعليمي" إلى **نظام تشغيل عائلي** (Family OS) فيه كل أسرة لها مستأجرها المستقل (Tenant) الخاص بها، والنظام التعليمي الحالي أصبح **وحدة واحدة** من وحدات النظام.

---

## ١) الطبقات (Layers)

```
┌─────────────────────────────────────────────────────────┐
│  الواجهات (UI) — عربي/إنجليزي، موبايل أولاً              │
│  لوحة الأسرة · لوحة التعليم · لوحة الصحة · الروبوت       │
├─────────────────────────────────────────────────────────┤
│  طبقة المنطق (Server Actions + API) — كل وحدة Module    │
├─────────────────────────────────────────────────────────┤
│  طبقة الوصول للبيانات (DAL) — lib/auth + lib/tenant     │
│  ✅ عزل المستأجرين + الحسابات + الصلاحيات                │
├─────────────────────────────────────────────────────────┤
│  قاعدة البيانات — PostgreSQL (Prisma)                   │
│  النظام التعليمي (الموجود) + Person/عائلة + ذاكرة + صحة │
└─────────────────────────────────────────────────────────┘
```

## ٢) نواة النظام الجديدة

| المفهوم | الوصف |
|---|---|
| **Tenant (مستأجر)** | كل عائلة مستأجر مستقل فورًا. المؤسسات (أكاديمية/روضة) مستأجر من نوع PROVIDER/INSTITUTION |
| **Person (توأم رقمي)** | كل إنسان في النظام له سجل (اسم، ميلاد، جنس)، وحساب الدخول اختياري |
| **Family (عائلة)** | مجموعة أشخاص داخل المستأجر مع أدوار (أب/أم/طفل/جد) |
| **Relationship (علاقة)** | علاقة موجهة بين شخصين (ولي لطفله، زوج لزوجته، أخ لأخته...) |
| **وحدة التعليم** | النظام التعليمي الحالي كاملًا (دروس خصوصية + حضانة) — يبقى الوحدة الأساسية الأولى |

## ٣) قرارات معمارية رابحة

- كل عائلة لها **Tenant** من اليوم الأول (الأعلى تكلفةً والأصح للتوسع).
- كل إنسان **Person**؛ الحسابات القديمة (User) تُربط اختياريًا بـ Person عبر `userId`.
- الترقية **إضافية فقط** (additive): الجداول القديمة تفضل موجودة، الجديد يُضاف مع backfill وfeature flags.
- العزل يبدأ من **طبقة DAL** (`lib/tenant.ts`) تدريجيًا، مش إعادة كتابة كل شيء بين عشية وضحاها.
- النوافذ الإشعارات الرئيسية: **Telegram** أولاً ثم البريد/الإشعار الداخلي.
- الذكاء الاصطناعي: **Gemini** افتراضيًا، مع إدارة مقدمي الـ AI من لوحة الإدارة (بما فيها النماذج المحلية عبر Ollama).

## ٤) الوحدات المخطط لها (Modules)

1. **وحدة التعليم (Education)** — موجودة ومرتبطة بالعائلة.
2. **لوحة الأسرة + التقويم + الخطة اليومية** (Family Dashboard & Planner).
3. **الصحة (Health)** — نمو/تطعيمات/نوم/غذاء/أدوية/ملفات/تصدير PDF.
4. **المساعد الذكي (AI Assistant)** — توصيات وتفسيرات مبنية على بيانات العائلة.
5. **ذاكرة العائلة (Family Memory)** — إنجازات وأحداث الحياة وصور.
6. **شبكة المعرفة (Knowledge Graph)** — مستخرجة آليًا + قابلة للتعديل يدويًا.
7. **الروبوت (Telegram Bot)** — مدخل ومخرج أساسي: يسأل "إيه اللي حصل النهارده؟" ويبعت الخطة اليومية.

## ٥) البنية المستقبلية للنشر

- **السنة الأولى:** سيرفر Docker ذاتي الاستضافة (Ubuntu) — كل الخدمات في جهاز واحد.
- **الجاهزية للكلاود:** البنية قابلة للنقل إلى بيئة سحابية (ملفات رفع → MinIO/S3، LLM خارجي → Gemini، إلخ).
- **التسجيل:** LiveKit + Redis + Postgres + Egress.
